# 交付状态、权利与权限

在任务将改变提交/远端/可见性/发布状态，或存在实质权利疑问时读取。继续使用已有授权；方法选择和测试成功都不能授予新权限。

## 每个状态需要自己的证据

| 动作 | 执行前确认的具体对象 | 完成证据 |
|---|---|---|
| 准备本地候选 | 输入、目标根、允许修改、源保护 | 候选文件与身份、有效验证结果 |
| 提交本地改动 | 仓库、分支、stage 内容、身份 | commit ID 与树；没有夹带未授权文件 |
| 创建远端仓库 | owner、name、初始 visibility、目的 | 实际远端身份、URL、可见性回读 |
| push | 精确 remote、refspec、提交及历史范围 | 远端 ref 与本地目标一致 |
| 改 visibility | 精确仓库与目标可见性 | 平台回读与公开可访问检查 |
| tag / Release / 包发布 | 精确版本、提交、附件/包内容、发布目标 | 实际对象、版本、附件身份与可访问状态 |
| 部署 | 环境、构建输入、配置、执行范围 | 部署结果与所需运行检查；不等同业务验收 |

这些状态不是每次必经的流水线。只交付本地候选时不创建远端；只更新文章时不加 Release；用户明确授权完整发布时则不要在做完扫描或生成计划后停止。用户已经授权的精确动作不反复请示。

对含糊的“准备公开”，默认完成可审查候选；不要把它扩张成改变远端 visibility。对明确指定仓库和公开发布动作，按已给权限完成。确实缺少新外部动作授权时，先完成所有不依赖它的工作，给出具体对象、将发生的变化与唯一阻塞点。

## 源、index、commit、remote 不相互替代

提交前审查实际 stage；工作树干净扫描不覆盖不同的 index。提交生成新的 message/metadata 后，检查即将交付的 exact ref 与必要历史；原工作树回执不能自动为新 commit 的历史背书。push 前重新核对候选身份，防止验证后发生改动。

从已有仓库创建 clean projection 时，不复制 `.git`；新历史保留需要的来源说明。保留历史时，使用明确 refspec；不要顺带推送其他分支、tag、notes 或 refs。只有审查并获得授权才重写已发布历史、force push 或删除远端对象。

远端和托管 CI 状态需实际回读。命令退出成功但目标身份不匹配、CI 尚未完成、附件未上传或服务仍不可达，都不是预期交付完成。私有远端存在不证明公众可见；公开仓库存在不证明部署可用。

## 权利与来源按内容判断

保留既有且适用的许可证、版权、NOTICE 与来源。公共可见不意味着可以重新许可；作者自己的代码、上游代码、依赖、样例数据、图片/字体和研究资料可能有不同约束。Git 历史清除、路径替换或自动生成不消除来源义务。

对成熟项目检查真实新增/移动内容是否仍在既定许可范围内；不要无故重新发起许可证设计。缺少明确权利或存在实质冲突时，先隔离受影响内容、查权威依据并说明选择。不要为了完成清单擅自赋予 MIT 或宣称所有内容均可再分发。

有合理许可但不适合公开的私人数据仍应去除；已脱敏数据也不自动获得再分发权。必要的法律判断应明确其依据与不确定性，不让规则扫描器生成法律结论。

## 发布产物是新的公开面

检查实际打包结果，包含/排除规则、生成文件、source map、source archive、日志、附件、文档部署和元数据可能不同于源树。绑定包/附件 hash 与对应候选，验证读者拿到的产物。工作树通过不自动延伸到发布产物。

发布说明以实际变化、兼容性和限制为准。不要从计划文本生成已实现功能列表；不要使用“production ready”“安全认证”“可复现”等超出证据的措辞。

## 中断与恢复

外部动作前记录确切目标与预期结果，动作后回读，避免超时后重复创建或重复发版。状态不明先观察，不盲目重试。发生部分完成时报告哪个状态已到达、剩余对象与最小恢复动作；不尝试通过未授权删除或 force push 还原。

完成后返回实际交付层级、对象链接/标识、有效检查和剩余限制。给用户下一步命令时标注“未执行”，不能把命令本身当作证据。
