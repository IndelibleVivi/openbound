# 选择、提取与源关系

在组件离开父系统、候选来自选择/生成或源与公开副本关系影响写入位置时读取。先确定能够公开的对象，再选工程手段；不要求每个项目接受通用化改造。

## 分开决定关系与来源

| 关系 | 写入与验证的实际含义 |
|---|---|
| 就地整理原项目 | 保留原项目权威，检查工作区/index/ref；历史是否公开另作决定。 |
| 创建新的公开原件 | 选择新根目录与历史；此后公共项目可以成为唯一权威。 |
| 单向公共投影 | 私人源、选择规则和生成器共同决定候选；公共输出不反向覆盖私人源。 |
| 组件提取 | 验证新根目录内的独立接口、依赖、测试和可用性；父系统通过不够。 |
| 独立公共对应物 | 解释来源关系，允许公共实现与私人实现分别演化；不承诺自动同步。 |

另外确认作品是作者原作、上游 fork 还是独立衍生作品。清洁 Git 历史不会消除署名、许可证、NOTICE 或第三方数据的义务；保留历史也不自动证明来源完整。需要处理具体权利时转到 `delivery.md`。

这些是推理工具，不是要求用户填写的枚举。选择足够清晰后立即继续工作。

## 转换契约要小而真实

在动手前用已有上下文确定四件事，普通一次性任务可留在对话中：

- **输入**：所选源版本、文件/目录、作者材料；注明未提交修改是否属于输入。收集最小材料，不默认复制整个工作区。
- **允许改变**：路径/配置/接口适配、示例替换、编辑程度；必须保留的行为、作者意思与来源。
- **输出**：隔离根目录、公共形式、历史策略、需要支持的读者动作。
- **成功条件**：在候选根目录可运行的检查；关键机制的见证；读者能够理解的关系；已声明但暂不能验证的限制。

持续投影才需要可重放选择规则与私有回执。不要把机器执行所需的配置误当成公众必须看到的材料，也不要公开源路径、私人文件清单或内部删改理由。

## 隔离输出

优先显式 include/export。清空目标或递归复制前确认所有权；不把用户已有目录当作一次性临时目录。拒绝源与目标相互包含、路径越界、符号链接逃逸和未知目标内容。候选先在新临时根构造，验证后替换受管理输出；失败保留上一个有效候选。

内置 `project_candidate.py` 可处理明确的文件选择、按预期次数的字面替换、身份回执、幂等重放与漂移拒绝。它不理解业务含义，不做任意代码搬运，也不自动迁移 Git 历史。需要语法转换或构建导出时使用项目已有工具，把选择器/生成器作为有效证据的依赖记录下来。

未知代码、构建钩子、远端依赖不是读取操作。执行前确认其来源和预期副作用；检查命令同样可能上传日志、读取宿主凭据或触发发布。只在实际需要时打开处理出口或贡献隔离方法。

## 私人依赖的取舍

逐一判断组件要保留的关键机制依赖什么：模块、服务协议、数据形状、配置、文件路径、账户、构建环境或工作习惯。不要将所有私有依赖统一替换成空 stub。

- 有公共等价依赖：适配并在新根实际验证。
- 是机制的可替换边界：定义小接口，提供真实可运行的本地实现或受测 fixture。
- 是作品意义的一部分：公开可解释的契约、失败条件与参考适配器；诚实限定独立运行范围。
- 无法公开且无法替代：缩小公共承诺、换公共形式或选其他组件。不要声称已经解耦。

提取时同时检查隐性耦合：相对父目录导入、`PYTHONPATH`、全局安装包、dotfiles、缓存、个人 CLI、私有 registry、隐藏环境变量、构建上下文和测试对父仓库的访问。

## 在新根验证独立性

在干净的新根或容器/临时环境执行公开入口，使用公开安装说明与允许的依赖。不让父系统、私有服务、个人缓存或账户替候选提供缺失能力。不能获得真实干净环境时，明确环境限制，并执行能够验证的静态与运行检查。

用一个足以暴露关键失败条件的示例检验接口适配。分页器至少覆盖多个页和结束条件，重试器至少覆盖首次失败与边界次数，排序/采样实验保留相关分布；最小 happy path 不等于机制保真。

候选测试通过后核对可安装产物、README 路径和示例使用的是同一根。公共发行包漏打模块、安装后找不到资源或依赖父目录，都属于未完成提取。

## 返回原任务

带回所选对象、关系、允许转换、已验证的独立使用路径，以及剩余私人依赖的公开说明。若来源关系已改变，修正受影响的维护/交付安排；不重做其他已有效的检查。
