# 公开范围、历史与处理出口

在将交付的表面包含历史/媒体/生成物，或发现敏感线索、间接披露与外发行为时读取。深度由实际暴露面与威胁决定；没有命中不免除已选表面的覆盖责任，也不自动触发与任务无关的全组织安全审计。

## 先界定实际会离开私人环境的内容

以本次交付为准：工作树、index、选定 ref、可达历史、注释标签、LFS 对象、submodule、安装包、Release 附件、网站、图像、二进制、日志和运行输出都可能不同。只扫描工作树不能证明即将 push 的提交安全；扫描一个分支不能覆盖所有标签或其他分支。

对成熟一次性 clean projection，验证所选新候选及新历史，保留“原私人历史未交付”的准确范围；无需先净化所有私人历史。若保留原历史，检查实际将推送的 refs 及其可达对象。避免 `push --mirror`、`push --all`、自动附带标签改变已审查范围。

从下列线索选择必要检查：真实 token/密钥、个人配置/路径/身份、私人主机/账户/拓扑、内部 URL、客户数据、license/来源、附件元数据，以及多份材料组合揭示的关系。敏感程度由语境决定；示例占位符可能误报，貌似普通的两个公开事实组合也可能敏感。

## 使用候选检查器，读取覆盖而非绿灯

`inspect_public_candidate.py` 检查选定的文件与 Git 表面，报告对象身份、规则命中和覆盖缺口。示例命令见 `continuation-and-tools.md`。

审阅报告时一起读：

- `subject`：本次实际观察的候选与表面身份；不是用户记忆中的“这个仓库”。
- `rules`：规则版本与内容身份；规则变化会使旧结论失效。
- `coverage`：已观察、受限、未观察和不适用的范围，以及限制原因。
- `findings`：审查线索，不是上下文无关的判决。
- `claims`：只接受与上述证据相称的窄声明；`publication_ready` 始终不能由扫描器设为真。

原有兼容字段不等于新保证。`scan_complete` 即使为真，也只能按该版本定义解读；使用明确的 coverage/claims，并在报告中说清“对哪些对象、哪些规则、哪些表面未发现命中”。二进制、过大内容、不可读对象、指针目标缺失、浅历史、未检查的标签/附件和语义识别盲区都要保留其边界。

报告不应包含命中的秘密原文。报告仍可能包含敏感路径或对象关系，默认保存在候选之外，不自动上传到 issue、PR、CI artifact 或公共仓库。

## 三个不能再漏掉的边界

### Commit message 与 metadata

检查实际交付历史中的 commit message，保留可定位的对象身份但不打印匹配原文。敏感内容可能只在消息、作者/提交者信息或标签注释中，文件树完全干净。不能把 blob 检查称作“完整历史检查”。

发现泄漏后，选择在隔离副本中重写相关历史，或在用户允许的新历史候选中重新建立可公开的来源说明。不要破坏原私人仓库，也不要为了清理身份随意丢失署名义务。历史重写与远端 force push 是不同权限和风险。

### Shallow/不完整历史

`--history-ref` 必须确认所选历史是否能遍历到真实根、对象是否可读。浅边界或缺失对象使全历史声明不成立；返回限制而非正常完成。需要完整旧历史时，在合适环境取得缺失历史并重查；本次只交付新历史时，则验证新历史并准确排除旧历史。不要仅删除 `.git/shallow` 以伪装完整。

### LFS 指针与 payload

识别 LFS 指针并记录 payload 未被证明检查。指针中只有版本、OID、大小等，并不等于实际文件内容。即使本地有对象，也必须确认 OID/大小与实际交付对象一致，并按类型检查；不能假设 `git lfs pull` 成功就完成脱敏。

当前内置检查器即使发现本地 LFS 缓存，也仍报告 `lfs-payload-unobserved` 和覆盖不足：它没有验证 payload，不能给它背书。它不会自动联网获取 payload。需要下载或调用外部内容解析器时先判断数据流向与授权，将 payload 的身份和专门验证结果另行绑定。二进制 payload 的文本规则检查不能替代图像/文档/元数据审阅。

## 修复与误报

修复候选并重检受影响表面。示例 token 等误报必须在上下文中确认；不要为了获得零发现而删除规则或创建通配豁免。确有长期豁免需求，范围绑定具体对象、规则和解释，修改后失效；不要把整仓标记“可信”。

排除文件要检查下游引用、打包、文档和运行路径是否仍依赖它。脱敏替换要保留机制；危险条件被示例清洗掉时转到 `expression-and-evidence.md`。

若真实凭据曾越过边界，删去候选中的值不能撤回既有披露。清楚告知实际受影响范围并处理用户授权的撤销/轮换动作；不猜测凭据是否有效，也不向服务发送验证请求。

## 转换过程本身的数据出口

在使用联网模型、外部图渲染、在线 secret 检测、第三方翻译/托管、包安装、构建钩子和 CI 上传前，确认会发送什么。工具可用不等于敏感材料可以发给它。优先本地处理与最小必要输入；不要把整仓、完整日志或秘密匹配值发送出去解释一个局部问题。

调用其他 Agent 同样是上下文流动：只传任务需要的片段和已确认结论。保存回执前避免原始日志、替换值、私人绝对路径等无必要内容。临时文件与缓存也可能携带原文；保持在授权环境和适当生命周期内。

## 组合披露与风险升级

普通独立工具无需维护全网情报台账。若项目暴露账户/拓扑、连续发布多份切片、读者可能据此定位私人系统，比较本次变化与已知公开材料，检查是否共同揭示身份、访问路径、服务关系或数据来源。记录影响结论的关系，不默认抓取作者的全部线上生活。

完成后返回已修复内容、误报判断、精确覆盖限制和能支持的声明。尚未观察但与本次交付无关的私人面不用修；与本次交付直接相关的未覆盖面必须处理或清楚缩小交付范围。
