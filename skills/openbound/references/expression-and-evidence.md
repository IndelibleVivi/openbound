# 公共表达与证据保真

在作品是方法、实验或构想，或替换数据/环境可能改变机制时读取。目标是做出有用、有意思且诚实的作品；不把材料包整理成审查表就宣布完成。

## 从读者能获得什么开始创作

找出原材料中值得公开的具体价值：可复用技巧、独特机制、失败发现、问题的新表述、可检验猜想、设计约束或可供他人改造的原型。选能承载它的形式：短文、方法说明、参考实现、交互演示、实验记录、Blueprint 或组合。无需将未完成思想包装成软件产品。

完成实质性创作：选择结构，补足机制解释，制作例子，改进标题和节奏，解释适用条件。保留作者的重要立场和区别；允许重写表达，不能悄悄更改原有结论。对作者未表达但有帮助的新推论，说明它是新增解释或待验证建议。

不要强迫每句贴标签。只在读者可能误解的实质性主张处，使来源关系清楚可辨：作者观察、私有记录、候选复现、新增推理或假说。读者能判断证据强度，比术语数量重要。

## 区分四种可交付证据

| 依据 | 能够支持的说法 | 不能替代的说法 |
|---|---|---|
| 原作者私有环境观察 | 作者曾在所述条件下观察到的现象；披露条件不足时注明限制 | 公开读者已经能独立复现，或其他环境具有同样效果 |
| 选定且可公开的测量/记录 | 在已描述样本和方法中的结果 | 未测量人群、条件或因果结论 |
| 合成示例的实际运行 | 示例保留并展示了所选机制/错误条件 | 真实数据效果、普适性、性能或研究结论得到验证 |
| 设计与论证 | 思路、自洽关系、可实施假说和下一可证伪预测 | 已实现、已观察或已获实验确认 |

私有证据不能公开时，可提供准确的方法摘要、样本边界、观察条件、反例与可公开的缩小演示。若无法检查原记录，使用作者报告的归属措辞；不要发明数字、运行记录、引用或第三方背书。

## 合成替换应保留什么

先确定必须保留的机制或错误条件，再生成数据。保留的是因果/结构约束，通常不是原字段名或漂亮的正常输出。

例如：

- 去标识化排序样例仍保留产生相同优先级冲突的关系。
- 分页组件仍有跨页状态、重复边界和结束条件，不能把所有数据塞进单页。
- 关于异质性的研究仍有能区分假说的组间差异，不能把分布平均后声称现象被保留。
- 展示重试风险的例子保留非幂等副作用，不能改成无状态 mock 后说风险已验证。

把机制写成可检查的见证：输入条件、预期关系/失败、执行入口与观察结果。见证可以是测试、数据断言、渲染对比或人工推理检查；必须说明是哪种。先验证私有基准是否真的表现出所述现象，再在公共替代上检查同一性质；无法访问基准时只证明替代的局部性质。

使用包内见证/验证工具时，检查其候选绑定和日志策略。程序记录的是某个命令与输入的结果；业务断言需要项目自己的真实测试，不能把 `exit 0` 当成机制保真。

## 保留不成熟作品的价值

Blueprint 的完整性可以是：问题可理解、机制足够具体、设计取舍可争论、关键未知可定位、下一次检验能够区分结论。它不需要冒充已实现项目，也不必强行生成安装说明、CI、贡献模板和版本号。

实验文章至少让读者知道观察了什么、如何观察、在哪些条件下成立、已知反例是什么，以及解释仍有哪些竞争版本。不要为了叙事流畅去掉失败结果；可以压缩不重要的过程噪声，但保留影响结论的尝试。

方法说明给出可执行动作、何时适用、判断分叉和失败恢复。个人经验可以带有限制地发布，不必先完成正式科学研究。

## 可读性与图

先让目标读者能回答“它解决什么，关键机制如何工作，我能据此做什么”。图能解释关系时使用 `reader-and-facilities.md`；图中事实只能来自允许公开的材料。未实现部件用清楚的图例/文字区分，避免把未来设计画成已经运行的系统。

在完成前进行一次盲读式检查：隐藏内部笔记，仅看公共作品，能否理解关键机制、依据和未解问题？作者自述、确定性测试和 Agent 阅读判断是三种不同证据；需要真实目标读者评估时明确尚未获得。

## 返回原任务

带回完成的公共作品、保留的机制/意义、重要新增解释，以及哪些说法被验证、由作者报告或仍属假说。若转换改变了原公共承诺，更新承诺后继续；不要重新开始一个泛化产品发现流程。
